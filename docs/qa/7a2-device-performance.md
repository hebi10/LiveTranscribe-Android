# 7-A-2 Android 실기기 성능 측정

## 목적과 범위
PR #34의 세션별 인식·번역 처리 시간(최근 20건의 평균·최대)을 기기 관찰값과 대조합니다.
이 스크립트는 이미 켜진 앱의 프로세스 PSS, CPU 사용률, 배터리 온도와 잔량만 주기적으로 읽습니다.
음성·인식문·번역문·로그캣·화면 캡처·기기 ID는 수집하지 않으며 앱 시작/종료, 권한 변경을 하지 않습니다.

## 준비
- Python 3.10+, Android SDK Platform Tools(ADB), USB 디버깅이 허용된 실제 기기.
- `adb devices`에서 승인된 기기를 확인하고 테스트용 APK(`com.hebi.livetranslate.debug`)를 설치합니다.
- 앱 내에서 모델을 준비합니다. 약 2.12GB 모델 다운로드는 수동으로 완료하고 측정 전에 모델 검증을 마칩니다.
- 테스트 앱의 번역을 수동으로 시작하고, 음성 캡처를 허용한 영상 또는 마이크 입력을 선택합니다.
- 기기 이름/일련번호, 영상 제목, 실제 대사 및 개인정보는 결과에 기록하지 않습니다.

## Windows PowerShell 명령
```powershell
python scripts/device_perf_probe.py --package com.hebi.livetranslate.debug --duration 300 --interval 5 --output measurements/session-01.csv
python -m unittest scripts/test_device_perf_probe.py
```

생성 파일은 `session-01.csv`와 `session-01.json`이며, 같은 이름 파일은 덮어쓰지 않습니다.
`measurements/`는 개인 측정 자료이므로 Git에 올리지 않습니다. 공개 이슈에는 익명화한 통계만 기록하세요.

## 측정 조건
각 조건에서 동일한 영상 및 기기를 사용하며 최소 3회 측정합니다.
1. 5분 일반 자막: 오디오 출력을 유지한 영상.
2. 15분 연속 대화: 발화가 많은 영상과 동일 입력 설정.
3. 30분 장시간 실행: 발열·배터리·메모리 증가 확인.
4. 일시정지/재개 및 종료: 중복 자막·대기열 생략 수·종료 안정성 관찰.
5. 팝업과 분할 화면: 각각 독립 세션으로 비교.

세션마다 모델 준비 여부, 시작 시 잔량, 충전 여부, 음성 입력 방식, 화면 배치, 언어 모드, Android 버전, 사용 기기 등급(저/중/고)을 별도 *비식별* 테스트 기록에 남깁니다.
앱 화면의 최근 인식/번역 평균·최댓값 및 생략된 작업 수는 사람이 수치만 기록합니다.
CPU 값은 `dumpsys cpuinfo`의 OS 집계 시간창 사용률이고, PSS는 프로세스 메모리 사용량입니다.
배터리 온도는 기기 전체 배터리 센서 값으로 CPU/GPU 온도가 아니며 앱 단독 발열을 의미하지 않습니다.
영상 재생 시점과 자막 표시 시점의 직접적 시간차는 이 측정으로 구할 수 없습니다.

## 통과 기준(초기 기준, 측정 결과로 보정)
- 30분 실행 동안 비정상 종료, ANR, 모델 해제 중 충돌이 없어야 합니다.
- 인식/번역 대기열 누락 안내가 발생하면 누락 건수와 재현 조건을 기록합니다. 누락이 없었다고 가정하지 않습니다.
- 5/15/30분 측정의 PSS 추세 및 온도 변화가 지속적으로 증가하는지 검토합니다.
- 실제 재생 위치 대비 자막 지연을 확인하려면 별도 영상 타임코드 실험이 필요합니다.
- 기존 기준 빌드와 변경 빌드를 *같은 기기/동일 영상*으로 A/B 비교하기 전 성능 향상을 주장하지 않습니다.

## 제한
ADB 접근 및 `dumpsys cpuinfo`/meminfo 출력은 기기 제조사·Android 버전에 따라 다릅니다.
값을 추출하지 못한 경우 CSV를 빈 값으로 유지하며 0으로 보정하지 않습니다.
테스트 중 앱 프로세스가 종료되면 해당 샘플은 비어 있고, 재실행으로 PID가 변경되면 새 PID를 기록합니다.
