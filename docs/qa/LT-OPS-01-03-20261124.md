## 1. 결제 서버 운영 사전 점검

기존 LT-BILLING-01 문서의 운영 승인 및 보안 원칙을 그대로 따른다. 기존 PR #97의 Hebi App Release 결제 연결 필요 기록은 현재 운영 상태를 증명하지 않는다. 먼저 Play Console의 대상 앱(com.hebi.livetranslate)과 연결 Cloud 프로젝트를 실제로 확인한다.

Cloud Shell에서 운영 대상 프로젝트 ID를 확인한 뒤 아래 읽기 전용 스크립트를 실행한다. 실제 프로젝트 이름과 번호는 추측하지 않는다. 셸 변수에는 운영자가 확인한 공개 식별자를 넣는다.

~~~bash
python3 scripts/billing_ops_preflight.py \
  --project "$PROJECT_ID" --play-project-number "$PLAY_PROJECT_NUMBER" \
  --output measurements/billing-project-preflight.json
~~~

Cloud Run 서비스가 승인된 절차로 배포된 후에는 두 실제 서비스명과 지역까지 명시한다.

~~~bash
python3 scripts/billing_ops_preflight.py \
  --project "$PROJECT_ID" --play-project-number "$PLAY_PROJECT_NUMBER" \
  --region "$REGION" --gateway "$GATEWAY_SERVICE" --verifier "$VERIFIER_SERVICE" \
  --output measurements/billing-services-preflight.json
~~~

스크립트는 project 상태 및 번호 비교, 결제 연결, API 활성 상태, Cloud Run 준비/세대·서비스 수준 최대 인스턴스 1·동시성 8 이하, 별도 런타임 계정, verifier의 서비스 직접 IAM 정책, 게이트웨이 우회 주소 제한, 두 서비스의 동일한 번호 지정 Secret Manager 참조 및 실제 verifier URL 연결을 읽기 전용으로 검사한다. Secret 내용은 읽지 않고 원본 명령 결과·계정·Secret 참조·프로젝트 정보는 보고서에 출력하지 않는다.

PASS는 해당 메타데이터 검사만 통과했음을 뜻한다. UNKNOWN은 조회 권한 부족·서비스 미생성·확인되지 않은 값이며 통과가 아니다. FAIL 또는 UNKNOWN을 해결하기 전 운영 완료로 판단하지 않는다. 상속 IAM·조직 정책·Play Console 실제 연결 및 권한·LB/Cloud Armor 정책·이미지 다이제스트·예산·SDK 통신과 구매는 별도 확인한다. Cloud Run 게이트웨이는 외부 LB의 요청 제한을 우회하지 못하도록 ingress 및 기본 URL을 제한하고, 비공개 verifier의 접근 가능한 정확한 run.app origin을 유지한다.

공식 메타데이터 기준:
- https://cloud.google.com/run/docs/reference/yaml/v1
- https://cloud.google.com/run/docs/securing/ingress
- https://cloud.google.com/sdk/gcloud/reference/billing/projects/describe

## 2. 현재 내부 테스트 배포 결과 인계

OPS-09 영수증, 서명 AAB의 버전/패키지/해시 및 OPS-04 게시 결과를 실제 확인한다. 요청 versionCode 32가 실제 제공 버전이라고 미리 기록하지 않는다. 설치가 가능할 때 Play 내부 테스트 링크에서 업데이트한다.
https://play.google.com/apps/internaltest/4701453452188240193

Android 개발용 별도 패키지와 Play 설치본을 혼동하지 않는다. 이미 사용 중인 모델·기록을 지우거나 재설치하도록 요구하지 않는다.

## 3. Play 설치본 실기기 검증

먼저 배포 영수증에서 실제 versionCode 및 main SHA를 확인한다. USB 연결과 ADB 디버깅을 사용한다면 기존 debug APK 전용 검사 대신 Play 설치본 읽기 전용 도구를 사용한다. PowerShell 예시의 변수는 실제 영수증으로 채운다.

~~~powershell
[Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
python scripts/qa_real_play_preflight.py --expected-version-code $versionCode --source-sha $sha --output measurements/qa-real-play/preflight.json
~~~

자동 보고서는 실제 설치 버전, 설치 관리자, API, ABI, 에뮬레이터 흔적 및 모델 초기 공간을 확인한다. 설치 관리자 정보는 Play Integrity의 실제 판정이나 APK 커밋 증명에 해당하지 않는다. 저장 공간이 적어도 이미 검증된 모델을 보유한 기기는 무조건 재다운로드하지 않는다.

| ID | 실기기 작업 | 완료 조건 |
| --- | --- | --- |
| PLAY-QA-01 | 내부 테스트 설치 및 기존 데이터 유지 | 올바른 versionCode, Play 설치본, 기존 모델/설정/기록 보존 |
| PLAY-QA-02 | 모델 최초 준비 또는 이어받기 | 실제 SHA 검증 완료(READY), 네트워크 끊김 이후 복구 |
| PLAY-QA-03 | 영어·일본어 동영상 및 마이크 번역 | 실제 음성에서 한국어 자막 생성, 원문과 구분, 오류 안내 |
| PLAY-QA-04 | 팝업·버블·분할 화면, 큰 글꼴 및 폴드 전환 | 접기/펼치기·회전·태블릿에서 조작 가능, 자막 잘림 없음 |
| PLAY-QA-05 | 정지·재시작·권한 철회 | 즉시 오버레이 닫기 및 안전한 엔진 종료, 중복 세션/캡처 없음 |
| PLAY-QA-06 | 동일 영상 9회 성능 비교 | 기존 QA-REAL-01-B의 3조건×3회, 누락률·지연·CPU/PSS·온도 기록 |
| PLAY-QA-07 | 기록 동의 및 데이터 보존 | 기본 기록 OFF, 명시 동의 이후 저장 및 삭제, 개인정보 노출 없음 |

| BILLING-QA-02 | 운영 연결된 빌드의 실제 Play Integrity 준비 | 라이선스 테스트 계정에서 준비 확인, 변조/미인증/오류시 차단 |
| BILLING-QA-03 | 운영 연결 후 라이선스 구매 및 복구 | Play 가격·구매·재시작·복원·취소/만료·환불 상태 확인 |

모든 실기기 항목의 시작 상태는 NOT RUN이다. 결제 기능은 운영 변수 및 서버 연결을 반영한 별도 승인된 빌드가 필요할 수 있다. 실제 비용을 유발하는 구독 테스트는 라이선스 테스트 계정으로만 진행한다.

성능 수치 측정은 기존 QA-REAL-01-B 분석기·템플릿·시나리오를 유지한다. Play 버전은 성능 프로브의 패키지를 명시한다.

~~~powershell
python scripts/device_perf_probe.py --package com.hebi.livetranslate --duration 300 --interval 5 --output measurements/qa-real-play/correction_off-1-perf.csv
~~~

비공개 영상·음성·자막 원문·기기 일련번호·구매/무결성 토큰은 저장소 및 공개 Drive에 올리지 않는다.

## 4. 사전 코드 검증

- test_billing_ops_preflight.py: 합성 메타데이터, 권한 실패, 공개 invoker, 잘못된 프로젝트/URL/Secret 참조/한도 차단.
- test_qa_real_play_preflight.py: 정확한 설치 패키지/버전/설치 관리자/ABI/에뮬레이터 흔적 구분, 실제 추론·배포 성공 자동 판정 금지.
- test_billing_gateway.py: 기존 함수 수준 테스트에 loopback HTTP 요청 테스트 추가. 누락된 무결성 토큰, 내부 증명 위조, 잘못된 경로, 초과 본문, 403/429/503, verifier 증명 및 ready 검증. Google 및 Cloud Run에 실제 요청하지 않는다.
- 기존 Private Android APK의 Python regression tests에서 실행. 결과 확인 전 통과 주장 금지.

진행 중인 배포의 main SHA를 보존한다. 이 브랜치는 사전 준비이며 이번 internal AAB에 포함되지 않는다. 현재 배포 및 기존 PR의 CI가 종료되고 별도 병합 결정을 내리기 전까지 draft 상태를 유지한다. 이후 실제 운영 연결 승인 및 QA 근거를 확보하고, 변경된 앱 코드나 빌드 변수가 있으면 그 때 새 내부 테스트 배치를 확정한다.
