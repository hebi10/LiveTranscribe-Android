# LT-BILLING-01 — Play Integrity 구매 검증 게이트웨이

작성일: 2026-11-24
기준 main: 13af01dc0579dc29ea7287a796a113a15ec50b86 (PR #102 병합)
상태: 코드 구현 및 오프라인 테스트 추가. 실제 Cloud Run 배포, Play Console 연결, 라이선스 결제와 공개 개인정보처리방침 게시 미실행.

## 1. 구현 범위

- Android의 선택적 광고 제거 구독에만 Google Play Integrity 표준 요청(1.6.0)을 사용한다. 음성 인식·영상 번역·로컬 모델 경로는 변경하지 않는다.
- GET /verify 준비 확인과 POST /verify 구독 검증마다 HTTP 메서드·고정 경로·요청 본문 원본 바이트를 SHA-256으로 결합한다. 서버에서 같은 해시를 검증한다.
- 공개 게이트웨이는 Google의 복호화 응답에서 요청 패키지, 해시, timestamp, PLAY_RECOGNIZED, LICENSED, MEETS_DEVICE_INTEGRITY를 모두 확인한다. 검증되지 않은 요청은 비공개 검증기로 전송하지 않는다.
- 표준 요청의 Google 재사용 방지와 함께 단일 인스턴스 메모리에서 무결성 토큰의 해시 중복을 150초간 거부한다. 원문은 앱 코드에서 로그·DB·파일에 저장하지 않는다.
- 게이트웨이는 분당 60건의 복호화 요청과 8건 동시 처리 제한을 적용한다. 이것은 인스턴스별 보조 보호이며 외부 프록시 기반의 호출자별 제한, Cloud Armor, 예산/쿼터 및 최대 인스턴스 설정을 대체하지 않는다.
- 게이트웨이는 Cloud Run 메타데이터 ID 토큰의 audience를 비공개 검증기의 정확한 run.app 서비스 origin으로 지정해 호출한다. 서버 간 인증 증명은 Secret Manager로만 공급하고 APK에 넣지 않는다. 공개 호출자가 전달한 내부 인증 헤더를 사용하지 않는다. 리디렉션 금지.
- 서버 설정 누락, 승인되지 않은 APK/기기, 타임아웃, 무결성/구매 검증 오류에는 결제 버튼 비활성화 및 UNKNOWN 유지 원칙을 적용한다. 구매 성공, 구독 활성화, 환불 처리는 기존 Play Billing 및 subscriptionsv2 계약 유지. 실제 Play 설치 기기만 검증한다.

## 2. 배포 전 설정 (별도 운영 승인 필요)

| 대상 | 설정 및 검증 기준 |
| --- | --- |
| Play Console | com.hebi.livetranslate의 Play Integrity API에 사용할 Cloud 프로젝트 연결. 공식 Play 설치의 테스트 계정·라이선스·앱 인식 판정 확인. 설정 변경 전 현행 운영 앱 영향 확인. |
| Google Cloud | 연결 프로젝트의 Play Integrity API 및 Android Publisher API 활성화 여부 확인. 프로젝트 번호 및 서비스 계정은 실제 콘솔에서 확인하고 추측하지 않는다. |
| 비공개 검증기 | server/Dockerfile 사용. 인증 없는 호출을 허용하지 않고 전용 서비스 계정에 이 앱 구매 조회 최소 권한만 부여. 게이트웨이 계정에만 해당 서비스의 run.invoker 권한 부여. |
| 공개 게이트웨이 | server/Dockerfile.gateway 사용. 별도 서비스 계정에 Integrity 복호화 권한과 해당 비공개 검증기의 호출 권한만 부여. 서비스 계정 키 파일을 생성하지 않는다. Cloud Run은 초기 최대 인스턴스 1, 동시성 제한 및 예산·쿼터 검토. 호출자별 외부 제한은 신뢰된 LB/Cloud Armor에서 적용하고 직접 우회 주소 노출을 방지. |
| 환경 구성 | 게이트웨이의 BILLING_PRIVATE_VERIFIER_ORIGIN에는 실제 비공개 run.app 서비스 origin만 입력한다. BILLING_GATEWAY_AUTH_TOKEN은 두 서비스가 참조하는 서버 전용 Secret Manager 값(최소 32자)으로 구성. 인증 값 출력 금지. |
| GitHub google-play 환경 | BILLING_VERIFIER_URL: 실제 공개 게이트웨이 HTTPS /verify 주소, PLAY_INTEGRITY_CLOUD_PROJECT_NUMBER: 연결된 프로젝트 번호(공개 설정값). 미설정 상태의 디버그/릴리스에서 결제 비활성 확인. |
| 개인정보 및 광고 | Play Integrity 및 결제/광고 SDK의 실제 처리와 호스팅 로그 정책, Data Safety 신고·광고/구독 설정과 개인정보처리방침을 검토. 수정한 개인정보 HTML은 운영 승인 전 게시하지 않는다. |

기존 서명, 패키지 ID, Play 상품 ID 및 사용자 데이터 변경 금지. Cloud Run 리소스 생성이나 유료 API 연결, 운영 IAM 변경은 별도 승인 후 실행한다. Cloud Run 운영 상태 또는 실제 구매 성공은 코드와 CI만으로 판정하지 않는다.

## 3. 검증 순서

1. scripts/test_billing_gateway.py: 요청 해시 공통 벡터, 잘못된 패키지·본문·시간·판정, 중복 토큰, 요청 제한, 인증 실패 및 응답 자료형의 실패 차단을 네트워크 없는 mock 테스트로 확인.
2. BillingIntegrityHashTest: Android/JVM과 Python에서 동일 해시 검증. 기존 Kotlin 단위 테스트, privacy audit 및 CI 포함.
3. PR 최신 HEAD 필수 CI 및 코드 리뷰 확인 → 안전 병합 → main CI 확인.
4. 실제 설정/권한을 검증한 후 승인된 환경에만 게이트웨이와 검증기를 배포. 승인 없는 호출의 403, 서버 오류/설정 누락, 구독 준비 GET 및 권한 분리 확인. 실제 사용자 토큰/인증정보를 테스트 로그에 남기지 않는다.
5. 최종 내부 테스트 배포 별도 요청 후, Play에서 설치된 ARM64 실기기로 UMP 동의, 실제 구매 테스트, 복원, 취소, 환불, 네트워크 오류 및 오프라인 번역 영향 검증.
